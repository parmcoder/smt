# SMT v0.1.0 Production Plan

## Summary

This milestone prioritizes the module and starter restructure. It does not
implement `smt extend`; extension execution follows as a later milestone.
Beads is the delivery status source of truth. This document is a milestone
sequence, not a second task tracker.

See [[../specs/2026-08-17-smt-extensible-modules-design|SMT Extensible Modules Design]] and the canonical [[../../00-project/SMT - Implementation Spec|implementation specification]].

## Beads delivery map

The P0 restructure epic is `smt-4xf`, due 2026-08-23; its child issues are
the source of truth for delivery status. The deferred `smt extend` feature is
`smt-aah`, priority P3, due after 2026-08-24, and is blocked by the v0.1.0
release child. This map records ownership and sequencing only; it does not
duplicate Beads status.

The completed planning/decomposition task is `smt-4xf.11`. Its child ranges
are Web `.3.2.1-.3`, API `.3.3.1-.4`, Database `.3.4.1-.3`, Mobile
`.3.5.1-.3`, and Taskfiles `.6.1.1-.4`. Beads remains the live source of truth
for their status and sequencing.

## Milestones

1. **Design and contract (P0, current priority)** — record the five-layer
   model, decide the starter boundary, remove ambiguity around DevOps versus
   platform capabilities, and define the thin module metadata contract. No
   `smt extend` implementation.
2. **Version-1 starter restructure** — rewrite the planned blueprint around
   Web, Mobile, API, and Database; remove the DevOps prompt, `devops` stack,
   and combined `infra` repository from the new contract; add runnable
   Podman/Compose Web, API, and PostgreSQL operational skeletons plus a
   runnable Android/iOS Mobile starter.
3. **Safety and generated-workspace verification** — test selection and
   validation, deterministic offline apply, health/readiness, non-root
   runtimes, migrations, smoke commands, lockfiles, and absence of secrets or
   fake domain behavior. Keep current behavior claims unchanged until this
   milestone is accepted.
4. **Production candidate** — run repository quality gates and a disposable
   real-workspace review with Podman Compose. Record evidence and unresolved
   risks in the owning Beads issues; do not call the milestone complete from
   this document alone.
5. **Later: `smt extend`** — implement catalog resolution, dependency and path
   checks, dry-run/confirmation, Git-safe repository creation, and idempotent
   E2E scaffold extension only after the restructure is accepted.
6. **Later discovery** — evaluate AWS + Apptainer + OpenTofu as a concrete
   runtime/platform combination before adding implementation commitments.

## Release gates

The production tag requires accepted Beads work, clean repository state,
focused tests, `go test ./...`, `go vet ./...`, documentation consistency,
`git diff --check`, and human verification of the generated workspace and
Podman runtime. A failed safety or runtime gate blocks release. The release
must not imply that `smt extend`, Kubernetes, ArgoCD, AWS, Apptainer, or
OpenTofu execution is available.

## Assumptions and risks

- Version 1 has no external users, so the planned rewrite does not require a
  compatibility migration.
- The five layers stay in one repository until ownership and deployment
  boundaries justify extraction.
- The thin module contract is design-only in this milestone.
- The existing implementation may still generate DevOps-shaped output until
  the restructure is implemented; docs must label that distinction clearly.
- The reviewed runtime baseline is fixed for this milestone: Go 1.26.5, pgx
  v5.10.0, Next.js 16.2.9 on Node 24.18.0, Flutter 3.44.9, PostgreSQL 18,
  and Podman 5.8.3+ with a Compose provider. These targets are planned and
  must not be inferred as delivered here; exact generated assets remain owned
  by the relevant Beads tasks.
